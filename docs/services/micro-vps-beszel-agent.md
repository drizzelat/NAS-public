# Service: VPS Beszel agent

## Overview

Beszel agent on the Oracle VPS ingress host. Reports the VPS to the Beszel hub on
the NAS so the VPS shows up in the dashboard at `https://beszel.example.com`
alongside the NAS. Host metrics: CPU / memory / **root-disk** / network / temp,
plus **per-container Docker metrics** via a GET-only socket-proxy (see below).

The VPS is public and the hub is on the CGNAT'd NAS, so this agent uses the
**WebSocket** connection model — it dials **out** to the hub — instead of the
classic hub→agent dial-in the [NAS agent](beszel.md) uses.

## Stack

- **Stack folder:** `stacks/micro-vps-beszel-agent/`
- **Compose file:** `stacks/micro-vps-beszel-agent/docker-compose.yml`
- **Managed by:** the **Komodo Stack `micro-vps-beszel-agent`** on Server `micro-vps`, since

  The clone lives at `/etc/komodo/repos/nas` on the VPS.
- **Runs on:** the Oracle VPS ([host + SSH details](micro-vps-ingress.md)).

## Connection (WebSocket, outbound)

| Setting   | Value                                        | Why |
| --------- | -------------------------------------------- | --- |
| `HUB_URL` | `http://100.64.0.11:8090`                 | Hub over Tailscale — direct, no nginx loop, no TLS |
| `LISTEN`  | `127.0.0.1:45876`                            | Legacy SSH-tunnel listener pinned to loopback — nothing on the public IP |
| `KEY`     | Komodo Variable, from the vault (per-system) | Public key the hub shows when adding the system |
| `TOKEN`   | Komodo Variable, from the vault (per-system) | Authenticates the WebSocket connection |

Outbound-only means **no inbound port, no Oracle-iptables rule, nothing bound on
the public IP `198.51.100.10`**. The agent reaches the hub over the tailnet.

## Environment variables

| Variable                  | Description                                         |
| ------------------------- | --------------------------------------------------- |
| `BESZEL_VPS_AGENT_KEY`    | `KEY` — public key from the hub                     |
| `BESZEL_VPS_AGENT_TOKEN`  | `TOKEN` — WebSocket auth token                      |

Both are generated by the hub when you **Add System**, and are never committed in plaintext. The
vault (`secrets.enc/portainer-env/micro-vps-beszel-agent.env.age`) is the source. The Stack reads
them from the secret Komodo Variables `MICRO_VPS_BESZEL_AGENT__BESZEL_VPS_AGENT_KEY` and
`…__BESZEL_VPS_AGENT_TOKEN`, which `scripts/secrets.sh komodo-vars micro-vps-beszel-agent` writes.
To change one, run `secrets.sh edit micro-vps-beszel-agent`, then
`secrets.sh push micro-vps-beszel-agent`: for an owned stack, `push` writes the Variables and
deploys through Komodo.

## Disk monitoring (root fs, no host `/` exposure)

A container agent only sees its overlay, not the host's 45 GB root fs. Rather than
mount host `/` read-only (which would hand the agent `/etc/shadow` and every
secret — the same thing [stacks/beszel](beszel.md) refuses), an **empty probe dir**
on the root fs is bind-mounted to `/extra-filesystems/root:ro`. `statfs` of any
path on a filesystem returns that whole filesystem's usage, so this reports the
real root-disk numbers with **zero file exposure**. It shows in the hub as a
filesystem named `root`. Oracle Ubuntu 24.04 is a single root partition, so `/var`
(where the probe lives) is on the same fs being measured.

## Docker metrics via GET-only socket-proxy

`network_mode: host` is kept for real host network-interface stats. Per-container
metrics come through the `beszel-socket-proxy` sidecar (`tecnativa/docker-socket-proxy`,
same as the [NAS agent](beszel.md)), **not** a raw `/var/run/docker.sock` mount: a
`:ro` socket bind on a host-net container still lets the daemon API accept `POST`
(create/exec/bind-mount `/`) = host root. The proxy is GET-only
(`CONTAINERS`/`PING`/`VERSION`, `POST: 0`) and binds host loopback `127.0.0.1:42375`;
the agent reads container stats via `DOCKER_HOST=tcp://127.0.0.1:42375` with zero
write surface on the daemon. The proxy is capped at 0.25 CPU / 64 MiB — negligible on
the 954 MiB box.

## First-time setup

1. **Hub UI → Add System.** In `https://beszel.example.com`, **Add System**,
   choose the **WebSocket** connection. The hub emits a **KEY** and **TOKEN**.
2. **Put the env in the vault and deploy.** Put KEY and TOKEN into the vault as
   `BESZEL_VPS_AGENT_KEY` / `BESZEL_VPS_AGENT_TOKEN` (`./scripts/secrets.sh edit micro-vps-beszel-agent`),
   then `./scripts/secrets.sh push micro-vps-beszel-agent`, which writes the Komodo Variables and
   deploys the Stack. CI cannot do this step, because it holds no vault key. (Historically the
   stack was a Portainer Git stack, first added by hand in the Portainer UI; Komodo adopted it on
   2026-09-15.)
3. **Confirm online.** The VPS system flips to *online* in the hub once the agent
   connects out over the tailnet. If not, check the KEY/TOKEN match exactly (a
   single stray space fails auth) and that the VPS can reach `100.64.0.11:8090`
   (`sudo tailscale status` on the VPS, peer `nas` online).
4. **Thresholds / alerts** — set per-system CPU/mem/disk thresholds; alerts route
   like the NAS ([beszel.md](beszel.md)).

## Operations

> Edit `stacks/micro-vps-beszel-agent/`, then commit and push. `deploy-stacks` sends Komodo
> `DeployStack` and health-checks the result. By hand: Komodo → Stacks →
> `micro-vps-beszel-agent` → **Deploy**, or dispatch `deploy-stacks` with
> `stacks=micro-vps-beszel-agent`. On the host the `ubuntu` user needs `sudo docker`.

### Upgrade

`henrygd/beszel-agent` pinned to a **version tag**`@sha256:…` (see compose; moved off
`latest` so Renovate tracks version bumps, not just the digest). Keep it in step with
the NAS agent pin in `stacks/beszel/`.

### Common failures

- **Hub shows the VPS offline** → agent can't reach the hub. Check
  `sudo tailscale status` on the VPS (peer `nas` online), and that the KEY/TOKEN in
  the vault (and so in the Komodo Variables) match the hub's values exactly.
- **Whole VPS gone from the hub after a reboot** → `restart: unless-stopped` +
  docker-at-boot should relaunch it; if not, **Deploy** the Komodo Stack, or
  SSH in and confirm the container is up.
